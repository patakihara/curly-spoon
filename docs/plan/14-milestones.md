## Milestones

**Backend first**, as you asked: _"Forget the frontend for now. Go straight to the backend."_ M0 keeps the design system, canvas and Android foundations it already built; new frontend work waits for M5, where both apps catch up together, with parity. M1 to M4 build the server against your real servers, each slice exercised through a minimal web shell, used as the PWA on your phone. The shell grows with each milestone by the plain pages its exit needs (search, requests and a release picker, the song menu's Add to library, Browse, lists and The Digest): existing generated Sonora pages wired to real endpoints by hand-written data code, with no new design and no canvas matching. A milestone ends when **you** have used it, not when CI is green.

### M0 · Foundations

- **[M0.repo]** The rebuild happens **in the same GitHub repository**, so the F-Droid repository, signing secrets and release workflows carry over; the old code stays at the tag `legacy`. The first Android build installs over 0.2.0 as an update, naming its server from a repository secret.
  _Done when:_ (a) a test asserts the tag `legacy` exists and `main` has the top-level folders `server`, `web`, `android`, `schema`, `design/sonora`, `design/app` and `docs/plan`, and none of the legacy tree's `apps/` or `packages/`; (b) a test asserts nothing under `design/sonora/assets/reference/spotify/` is tracked, that path is gitignored, and every commit touching `design/sonora` has an author in the repo's allowed identity list; (c) a live test reads the F-Droid repository's `index-v2.json` and asserts `net.develivarr.auralis` at a version code above 0.2.0's, with an APK URL that answers 200; (d) Sofia's sign-off: it installed on her phone over 0.2.0 without uninstalling; (e) a test asserts both release workflows pass `-PauralisServer` from the `AURALIS_SERVER` secret, and CI asserts a release build without it fails.
- **[M0.schema]** zod → OpenAPI → generated TS and Kotlin clients, enforced in CI.
  _Done when:_ (a) a test regenerates the OpenAPI document and both clients from `schema/` and fails on any difference from what is committed; (b) a test adds a field to a zod schema in a temporary copy and asserts it appears in both the generated TS and Kotlin clients.
- **[M0.record]** Adapter record mode; the first recordings from mediaserver's Audiobookshelf and Jellyfin, with secrets scrubbed. The audio file call keeps its real status and headers, with a synthesized clip as its body.
  _Done when:_ (a) a test runs an adapter in record mode against a local fake upstream and asserts it writes the request and response as a recording; (b) a test asserts recordings from mediaserver exist for Audiobookshelf's library list, item detail and play calls and Jellyfin's library list and item detail; (c) a test scans every committed recording and fails on any token, API key, cookie, password or real hostname.
- **[M0.security]** Security baseline: one-time setup, admin role, cookie and proxy config.
  _Done when:_ (a) a test calls setup twice and asserts the second call is refused without an admin session; (b) a test asserts every admin route rejects a signed-in non-admin user; (c) a test asserts the session cookie is `HttpOnly`, `Secure` over HTTPS and `SameSite=Lax`, and forwarded headers are trusted only from the configured proxy.
- **[M0.sso]** **Multi-user from day one**: an `auralis` OpenID Connect client in the household sign-on, sign-in mapped by username to each person's Audiobookshelf and Jellyfin accounts, and device registration. Each person's upstream token is minted without their password: ABS by an admin key's `POST /api/api-keys`, Jellyfin by an API key authorizing a Quick Connect request.
  _Done when:_ (a) a test signs in through a recorded OpenID Connect exchange and asserts the username maps to that person's Audiobookshelf and Jellyfin accounts; (b) a test registers two devices for one user and asserts each gets its own device id; (c) a test asserts two users' upstream calls each carry their own token, never the other's; (d) a Playwright test opens a page signed out, signs in and lands there, and a refused sign-in returns showing why, the only error shown.
- **[M0.uikit]** **Sonora pipeline**: web UI package built from Sonora's components, by generators in `design-codegen/`, Android props generated from the `.d.ts` files, and every check in "Staying on track" but the string, format and icon checks (M5).
  _Done when:_ (a) a test rebuilds the web UI package and the Android props from `design/sonora`, fails on any difference from what is committed, and asserts every Sonora component with a `.d.ts` has a web export and a generated Kotlin props class; (b) a test feeds the repo's Claude Code hook an edit to a generated folder and asserts it is refused; (c) a test asserts the merge check fails when `design/` or `docs/plan` differs from the tree recorded in `design/published.json`; (d) a test asserts the commit check rejects an app change without a `Plan:` line naming an existing item; (e) a test runs the session-start hook on a fixture repo and asserts it prints milestone, done items, work in flight, next step, failing checks and outbox; (f) a test asserts the end-of-session hook blocks while a design or plan change is unpublished.
- **[M0.canvas]** **The Auralis canvas** in `design/app`: the structure in `nav.json` first, then every page drawn and compared with its Sonora UI kit render, Sonora pruned to what the pages use, and generators for the web router, the Android nav graph and the pages. **Both apps navigate the whole map with placeholder data.**
  _Done when:_ (a) a test asserts the web routes and the generated Android nav graph's destinations both equal the pages in `nav.json`; (b) a test asserts every Sonora component is used by at least one page, directly or inside a component a page draws, so `Icon`, the row shell and a panel header pass; (c) a Playwright test visits every page in `nav.json` and asserts it renders with placeholder data; that switching destinations or toggling the hamburger keeps the same rail element, its pills and width easing over `--duration-slow` as in Sonora Prime, none regrowing from icon width; that at 600 and 1024&nbsp;px the mini-player opens Now Playing as a side panel; that the panel's tab and the page never change each other; and that the phone sheet's tabs switch within one sheet, with no opening transition; (d) an emulator test in `android/app/src/androidTest` navigates to every destination in the generated Android nav graph and asserts each shows its page title with placeholder data; (e) a test asserts every page in `nav.json` has a comparison in `design/app/compare` with its phone and desktop renders, the Sonora UI kit render it names, a differences list and the hash of the page it was made from, and fails when the page has changed since; (f) a test asserts every page in `nav.json` has a complete structure block whose links name existing pages and a page file, and that the canvas build puts the flowchart and screen list alone on the start page and each page's structure and artboards on a canvas page of its own, linking to the start page and to the pages it leads to.
- **[M0.tokens]** Sonora tokens generated for web (CSS) and Android (`SonoraTokens.kt`), fonts and icons; web gallery and Android Paparazzi screenshots in CI, complete once every Sonora component has a preview card.
  _Done when:_ (a) a test regenerates the CSS tokens and `SonoraTokens.kt` from Sonora's token export, fails on any difference, and asserts both carry the same names and values; (b) a test asserts the container serves every font and icon itself, with no request to an outside host; (c) a Playwright gallery test produces a screenshot of every Sonora component in CI, and a Paparazzi test produces a screenshot of each token specimen and of each Compose component in `ui/sonora`.
- **[M0.states]** Material's states and disabled-without-an-action on every interactive Sonora component (see "Sonora, pruned and ordered"), in Sonora first, then both apps, so staging shows which controls work.
  _Done when:_ (a) a Playwright test renders each interactive Sonora component enabled, disabled, hovered, focused and pressed, and asserts the states differ, focus draws an outer ring, and a press ripples from the pointer without changing shape; (b) a Paparazzi test renders the same states of each such Compose component in `ui/sonora`; (c) web and Android tests assert a component with no action, or with `disabled` set, is disabled and ignores presses; (d) Playwright and emulator tests visit every page in `nav.json` and assert every control without a bound action is disabled.
- **[M0.plan]** This plan moved into `docs/plan` and published from there, with its checks, badges and hooks, and the orchestrator reading the whole plan at every start.
  _Done when:_ (a) a test runs the plan checks on `docs/plan` (unique ids, a done-when on every item, the size limit, no dated notes, the outbox format) and they pass; (b) a test renders a fixture plan and asserts the done, in-progress and next badges, the waiting-on-you box, recent decisions, the inbox ideas waiting to be sorted and the footer commit; (c) a test runs `progress.mjs --summary` on a fixture repo and asserts every summary line; (d) a test asserts `design/published.json` records the current tree of `docs/plan`; (e) a test runs the session-start hook and asserts it tells the orchestrator to read all of `docs/plan` first, on startup and after a compaction; (f) a test asserts the plan has a standing-rules section and that the subagent brief template begins with it.
- **[M0.staging]** The existing Auralis container on mediaserver is the test instance, following `main` until M1.release and the newest release after, and retires the old app's service worker. An open tab reloads when `/api/health` reports another commit, waiting while audio plays.
  _Done when:_ (a) a live test asserts the staging container's health endpoint reports the commit of the latest green `main` build, or after M1.release the newest release, within 30 minutes of its publish; (b) a Playwright test replaces a stand-in of the old caching worker with the one at `/sw.js` and asserts the tab reloads onto the new app, no cache or registration left; a test asserts `index.html` is never cached and hashed assets immutable; (c) a Playwright test changes the commit `/api/health` reports and asserts an open tab reloads, waits while audio plays, and reloads once it stops.
- **[M0.unverified]** "What this plan hasn't verified" kept current, as "Keep the plan clean and the progress true" says.
  _Done when:_ (a) a test asserts the plan checks fail on a line in "What this plan hasn't verified" naming an item that doesn't exist; (b) a test runs `progress.mjs --summary` on a fixture repo where an item named by such a line is done and asserts the summary lists that line as stale.
- **[M0.emulator]** The Android emulator in CI runs the app (log in, open Browse, play 5&nbsp;s), building the thin direct-play slice M1.play extends, against the recorded-upstreams server in `server/e2e/`, never in the image.
  _Done when:_ (a) an emulator test in CI logs in against the server with recorded upstreams, opens Browse and asserts playback passes 5 seconds.

**[M0.exit] Done when** you sign in to the staging container with your Delivarr account, it reaches your own Audiobookshelf and Jellyfin, and both clients render the shell from generated types.
_Done when:_ (a) Sofia's sign-off.

### M1 · It plays

- **[M1.index]** Local index job for Audiobookshelf and Jellyfin.
  _Done when:_ (a) a test runs the index job on the Audiobookshelf and Jellyfin recordings and asserts every recorded book, show, episode, album and track is indexed with its upstream ids; (b) a test asserts a second run after a recorded change updates only the changed items.
- **[M1.play]** `POST /play` for Audiobookshelf, with direct play and working HLS; gapless multi-file playback; chapters across files; the web and Android players, which M1.shell starts from its lists and Now Playing.
  _Done when:_ (a) a test on the Audiobookshelf recording that answers with an HLS playlist asserts `POST /play` returns a plan whose URLs the server proxies, and a segment returns audio; (b) a test on a direct-play recording asserts the plan's track URLs answer range requests with 206; (c) a Playwright test plays a two-file fixture book and asserts the second file starts without a pause and position continues across the boundary; (d) an emulator test asserts the same on Android; (e) a test asserts chapters spanning files map to the right absolute positions in the playback plan.
- **[M1.music]** Jellyfin play: `POST /play` for an owned track or album returns a plan the server proxies with range requests, an album as one gapless plan in track order.
  _Done when:_ (a) a test on a Jellyfin recording asserts `POST /play` for a track returns a plan whose track URL the server proxies and answers a range request with 206; (b) a test asserts an album plays as one plan with its tracks in order.
- **[M1.progress]** Progress to each item's own server, Audiobookshelf or Jellyfin; bookmarks.
  _Done when:_ (a) a test sends one progress update for an Audiobookshelf book and one for a Jellyfin track and asserts each reaches its own server's recorded progress calls, with wall-clock listening time; (b) a test creates, lists and deletes a bookmark and sees each Audiobookshelf call.
- **[M1.sessions]** Per-device listening sessions, stored on the server, unmixed by default. Their queues and autoplay as "Playback & queues" says, radio from owned music until M3. The queue style is set per session until M2.settings stores it per user.
  _Done when:_ (a) a test asserts two devices of one user keep separate sessions and queues on the server; (b) a test asserts the music and spoken queues advance independently and the meta-queue switch changes which one the controls drive; (c) a test asserts YouTube Music style and Spotify style insert items in their documented orders, and the default button actions follow what is playing; (d) a test asserts Back returns to the previously played item across both queues; (e) a test asserts autoplay continues with the next episode, the next book in the series, and the rest of the album followed by radio from music you own (Jellyfin's Instant Mix).
- **[M1.shell]** The minimal web shell the Milestones intro describes. You sign in, list every indexed book, show and album your own accounts reach (`GET /library/{medium}`; the personal view waits for M3.requests), open a book, show, episode or album (`GET /items/{ref}`), start playback, see progress and the queue, and use speed, the sleep timer (including end of chapter) and Media Session controls.
  _Done when:_ (a) a test on the recordings asserts `GET /library/{medium}` lists every indexed book, show and album the signed-in user's own Audiobookshelf and Jellyfin accounts reach, with their availability; (b) a Playwright test on the server with recorded upstreams signs in, opens the Books, Podcasts and Music lists and starts playback from each, through its item's page; (c) a Playwright test asserts Now Playing shows the position advancing and the queue page lists what plays next; (d) a Playwright test asserts speed changes the playback rate, the sleep timer pauses playback at its time and at the chapter's end, and Media Session metadata and actions are set.
- **[M1.release]** Releases, before "It plays" ships, as "How the work runs" says; M0.staging's live check follows the newest release.
  _Done when:_ (a) a test asserts a push to `main` publishes `:edge` and never `:latest`, and a release tag publishes `:latest`; (b) a live test asserts the mediaserver container reports the commit of the newest release.

**[M1.exit] Done when** you listen for a week through the web app, as the PWA on your phone and in the browser on desktop, and resume across both without thinking about it. This also replaces the ABS app for you.
_Done when:_ (a) Sofia's sign-off.

### M2 · My library

- **[M2.search]** Search over your library: suggestions from the index, relevance-ranked results. In the shell, tapping a song opens its album and its art plays it.
  _Done when:_ (a) a test asserts `GET /search/suggest` returns suggestions from the index for a two-letter prefix; (b) a test asserts an exact title match ranks above partial matches; (c) a test on the recordings asserts `GET /search` kind filters hide rows without reordering, every row is owned, results and suggestions stay within the user's own accounts, and recent searches stay per user; (d) a Playwright test on recorded upstreams types two letters into Search, sees suggestions with no `GET /search` call, submits, and opens and plays a result.
- **[M2.lrclib]** Lyrics: Jellyfin's own through `GET /lyrics/{ref}`, then LRCLIB backfill and cache.
  _Done when:_ (a) a test on Jellyfin's recorded lyrics asserts `GET /lyrics/{ref}` returns synced lines with their times; (b) a test on an LRCLIB recording asserts a track without Jellyfin lyrics gets synced lyrics stored in the cache; (c) a test asserts a second request for those lyrics makes no LRCLIB call.
- **[M2.lists]** Listening lists, podcast playlists, The Digest and custom digests.
  _Done when:_ (a) a test creates a listening list and a podcast playlist through the API and plays each in order; (b) a test asserts The Digest holds the new unplayed episodes of subscribed shows by its rule in "Lists that aren't queues"; (c) a test creates a custom digest from chosen shows and asserts its episodes; (d) a test plays a digest episode and asserts it is marked played while that show's Up next and autoplay stay where they were; (e) a test plays a digest and asserts the previous queue is saved, playing its current or next episode resumes it, and playing the digest or an episode from its page resumes the digest's queue.
- **[M2.sorting]** Library sorts, Random among them; Up next and second-most-recent on Browse (from owned content).
  _Done when:_ (a) a test asserts `GET /library/{medium}` sorts by title, artist and Random, and Random with a fixed seed gives that seed's order; (b) a test asserts Browse's Up next and second-most-recent shelves hold only owned items from the user's history.
- **[M2.settings]** Settings stored per user in `GET/PUT /settings`: theme, autoplay switches, first-run setup, and queue style, which retires `PUT /sessions/this/style`.
  _Done when:_ (a) a test round-trips every setting through `GET/PUT /settings`.

**[M2.exit] Done when** the minimal shell finds and plays anything you own, and your lists and The Digest play as you expect.
_Done when:_ (a) Sofia's sign-off.

### M3 · Play or get anything

- **[M3.requests]** The unified request pipeline and status vocabulary, and the record of who added what behind each person's own library.
  _Done when:_ (a) a test drives one request per medium through every status of the shared vocabulary on recorded upstreams; (b) a test asserts a failed step leaves the request in a named error status with its reason, and a retry resumes from that step; (c) a test asserts the library lists only what the user added, requested, subscribed to or played, unless the setting shows everyone's.
- **[M3.timing]** Books, first: time each step of today's pipeline on a real request.
  _Done when:_ (a) a test asserts a committed timing recording from a real request covers the Prowlarr search, the download, the import and the scan.
- **[M3.books]** Then Prowlarr and AudiobookBay (real tracker rows, recorded markup), qBittorrent, and the import job that replaces the four `audiobook-*` commands, with Audiobookshelf picking up just the new folder.
  _Done when:_ (a) a test on Prowlarr and AudiobookBay recordings picks the expected release; (b) a test on a qBittorrent recording adds the torrent and follows it to completion; (c) a test imports a fixture download and asserts folder layout, clean title, narrator only where needed, series and author photo; (d) a test asserts Audiobookshelf is asked to pick up only the new folder, never a full scan.
- **[M3.ytmusic]** Music: YouTube Music adapter (extractor in the container, daily canary-gated update), search, instant streaming with a disk cache, and YouTube Music radio for the last track joins autoplay's radio.
  _Done when:_ (a) a test on YouTube Music recordings returns search results and a stream the server proxies; (b) a live canary test resolves and plays 10 seconds of a known track from this server; (c) a test asserts replaying a recently streamed track is served from the capped disk cache with no upstream call; (d) a test asserts the extractor update job runs daily, records the version it promoted, and keeps the last passing version when a new one fails the canary; (e) a test on recordings asserts YouTube Music radio for the last track joins autoplay's radio after the album.
- **[M3.keep]** Songs: _Add to library_ in the song menu and automatically at ~90% played, saved as the original Opus with MusicBrainz tags, then a Jellyfin refresh.
  _Done when:_ (a) a test asserts Add to library saves the original Opus stream unchanged, with MusicBrainz tags; (b) a test asserts a track played past 90% is kept automatically, once; (c) a test asserts a Jellyfin library refresh follows each save.
- **[M3.albums]** Albums: always a lossless torrent via Prowlarr → qBittorrent, with multi-query search, release scoring, a one-tap picker for unclear matches and Auralis's own tagging import, replacing any kept songs from that album on arrival.
  _Done when:_ (a) a test on Prowlarr recordings runs several queries and ranks lossless releases by the scoring rules; (b) a test asserts an unclear match produces a picker choice instead of a download; (c) a test imports a fixture album with Auralis's tagging and asserts kept songs from that album are replaced.
- **[M3.spotify]** Spotify playlist import (read the public playlist, resolve each track on YouTube Music).
  _Done when:_ (a) a test reads a recorded public Spotify playlist, resolves each track to a YouTube Music id and reports the unmatched ones; (b) a test asserts the imported playlist plays in its original order.
- **[M3.podcasts]** Podcasts: subscribe or unsubscribe through PodcastIndex/iTunes search; greyed-out episodes that subscribe you when played.
  _Done when:_ (a) a test searches recorded PodcastIndex and iTunes results and subscribes and unsubscribes through Audiobookshelf's recorded calls; (b) a test plays a greyed-out episode of an unsubscribed show and asserts the subscription is created.
- **[M3.stubs]** Auralis takes over mediaserver's podcast stubs, adopting those already there and their rules (a hydrated file returns to a stub after 7 days unplayed); the old daemon and timer go. An hourly job stubs each subscribed regular-feed show's episodes in Audiobookshelf, never a YouTube channel's, and Auralis hydrates a stub when Audiobookshelf opens it. Its own players wait for neither: a stubbed or unstubbed episode plays from its feed enclosure through the range proxy, progress held until Audiobookshelf has it.
  _Done when:_ (a) a test on a recorded feed and Audiobookshelf's recorded podcast library asserts the job writes a stub for each episode without a file, none for a YouTube channel's, and a second run writes none; (b) a test seeds existing stubs and asserts the job adopts them without rewriting them, and returns a played, hydrated file to a stub after 7 days unplayed; (c) a test opens a fixture stub and asserts the open waits until its enclosure's audio fills the file; (d) a test on a recorded feed asserts `POST /play` for a stubbed or unstubbed episode returns a plan proxying its enclosure that answers range requests with 206, and progress on an episode Audiobookshelf lacks is held, then written once it appears; (e) a live test on staging subscribes a test feed, plays an episode at once, finds the show's stubs in Audiobookshelf within the hour, and opens one through Audiobookshelf's real API and asserts the file fills; (f) a live test asserts no old stub daemon or timer remains on mediaserver.
- **[M3.ytshows]** YouTube channels as audio-only shows through the generated feed, SponsorBlock segments cut from the files and skipped live, per-channel category settings, the show and its episodes flagged as YouTube in the schema, after a test channel runs through feed, download, cut and playback.
  _Done when:_ (a) a test asserts a fixture channel's generated feed lists its new upload as an episode with an audio-only enclosure and no video, and leaves a Short out by default; (b) a test cuts SponsorBlock segments from a fixture file and asserts the new length, and that live playback skips the segments; (c) a test asserts per-channel category settings choose which segments are cut; (d) a live test runs the test channel through feed, download, cut and playback on staging; (e) a test on recordings asserts a followed channel's show and episodes carry the YouTube flag in the schema, and an ordinary podcast's do not.
- **[M3.ytsync]** Watched-state and position sync for YouTube channels, as "Your YouTube account" says, starting with a test on your account.
  _Done when:_ (a) a test on recorded YouTube responses asserts played state and position sync both ways, only for added channels; (b) a test asserts sync stays off until a person opts in and uses only that person's cookies; (c) a test asserts expired cookies show the "sign-in expired" warning; (d) Sofia's sign-off: sync works both ways on her account.
- **[M3.catalog]** Search's global ranking across every outside source; artist and author catalogue with unowned titles; lyrics search.
  _Done when:_ (a) a test on recorded sources asserts search returns one list ranked across library and outside sources, an outside result above a weaker library match, kind filters that hide rows without reordering, each row's availability, and owned titles never requestable; (b) a test on recorded sources asserts `GET /people/{ref}` returns owned and unowned titles, the unowned requestable, and leaves them out with the setting off; (c) a test on an LRCLIB recording finds a track from a line of its lyrics; (d) a test delays one recorded source and asserts `GET /search` answers only once it answers or times out, with the same top result either way; (e) a test on recorded YouTube results asserts a matching channel ranks like a podcast, flagged as YouTube, and says whether it is followed.

**[M3.exit] Done when** any song you think of plays within a couple of seconds, your Spotify playlists are imported and play from your lists, and a lossless album you add arrives and replaces any songs you kept from it. Five books you request and two shows you subscribe to also turn into playable cards without you touching anything else.

- **[M4.handoff]** "Continue here" and "Play on…" between a user's devices.
  _Done when:_ (a) a test moves playback from one device to another with Continue here and asserts position and queue carry over; (b) a test asserts Play on reaches the user's own other device and never another user's.
- **[M4.streaming]** A streaming-only account for people without a media server.
  _Done when:_ (a) a test signs in a user with no Audiobookshelf or Jellyfin account and asserts Browse, search and YouTube Music playback work and library screens show their empty state.

**[M4.exit] Done when** Browse puts at least one thing you didn't own, and then wanted, in front of you each week. That's the bar from your brief: _"cleverly serve me audiobooks it thinks i will enjoy."_
_Done when:_ (a) Sofia's sign-off.

### M5 · Both apps, everywhere, polished

- **[M5.sonoraclean]** **Sonora without hard-coding or duplication.** Every literal size, colour, opacity, duration, easing, z-index, line-height and letter-spacing in Sonora's components becomes a token: an existing one where it matches, else new, exported as today, so M0.tokens' check holds web and Android equal.
